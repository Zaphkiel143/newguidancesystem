# AI Reply Generation - `.env` Setup Guide

How to fill in the **AI generation** block of the `.env` file for the E-Gabay
STI Guidance System chatbot.

---

## What this controls

The chatbot's natural-language replies are generated by `lib/ai.ts`, which reads
three variables from `.env` when the server starts:

```
# AI reply generation - any OpenAI-compatible endpoint (free Gemini tier here)
AI_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai
AI_API_KEY=your-api-key-here
AI_MODEL=gemini-3.6-flash
```

| Variable    | Required? | What it is |
|-------------|-----------|------------|
| `AI_BASE_URL` | Yes | Base URL of any **OpenAI-compatible** chat endpoint. The code appends `/chat/completions` to it, so it must NOT already end in `/chat/completions`. |
| `AI_API_KEY`  | Usually | Secret token sent as `Authorization: Bearer ...`. Only optional for a local Ollama server. |
| `AI_MODEL`    | Yes | The model name exactly as the provider expects it. |

**Fallback behavior (important):** if any of these is missing or the provider
errors, the chatbot does **not** crash - it silently falls back to the canned
replies from the intent classifier (`nlp_service/intents.json`). A broken setup
therefore looks like "the bot works but always repeats the same generic text".

---

## Step 1 - Create your `.env`

If you don't have a `.env` yet, copy the template in the project root:

```powershell
copy env.example .env
```

Then open `.env` and edit only the three `AI_*` lines. Leave
`DATABASE_URL`, `DIRECT_URL`, and `NLP_SERVICE_URL` alone unless you also need
to set those up.

---

## Step 2 - Get the values (recommended: free Gemini tier)

### Option A - Google Gemini (free tier, what this project ships with)

1. Open **https://aistudio.google.com** in your browser.
2. Sign in with any Google account.
3. Click **"Get API key"** (in the left sidebar), then **"Create API key"**
   (you can let it create a new project for you).
4. Copy the generated key (it typically starts with `AIza...`).
5. Paste it into `.env`:

```
AI_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai
AI_API_KEY=AIza...paste-your-key-here
AI_MODEL=gemini-3.6-flash
```

`AI_BASE_URL` and `AI_MODEL` can stay exactly as they are - only the key is
account-specific. The free tier has per-minute and per-day request limits; when
they're hit, the bot just falls back to canned replies until the limit resets.

### Option B - OpenAI

1. Open **https://platform.openai.com** and sign in.
2. Go to **API keys** (under your profile / project settings) and click
   **"Create new secret key"**. Copy it (starts with `sk-...`).
3. Fill in:

```
AI_BASE_URL=https://api.openai.com/v1
AI_API_KEY=sk-...your-key...
AI_MODEL=gpt-4o-mini
```

Note: OpenAI is paid-per-token; you need billing enabled on the account.

### Option C - Groq (free tier, fast)

1. Open **https://console.groq.com** and sign in.
2. Go to **API Keys** and click **"Create API Key"**. Copy it (starts with
   `gsk_...`).
3. Fill in:

```
AI_BASE_URL=https://api.groq.com/openai/v1
AI_API_KEY=gsk_...your-key...
AI_MODEL=llama-3.3-70b-versatile
```

### Option D - Ollama (local, offline, no API key needed)

1. Install Ollama from **https://ollama.com** and make sure it is running
   (`ollama serve` runs automatically after install on Windows).
2. Pull a model in a terminal: `ollama pull llama3.2`
3. Fill in:

```
AI_BASE_URL=http://localhost:11434/v1
AI_API_KEY=
AI_MODEL=llama3.2
```

`AI_API_KEY` can be left empty - the code simply omits the Authorization
header when the key is blank.

## Step 3 - Restart and verify

The values are read **once at server startup**, so restart the dev server after
editing `.env`:

```powershell
npm run dev
```

Then verify:

1. Open http://localhost:3000 and chat with E-Gabay.
2. **Working:** replies sound warm, conversational, and rephrase the official
   guidance answers differently each time.
3. **Not working:** every reply is the identical canned text for a topic -
   the AI generation is failing and the fallback is being used.

Optional direct test of your provider from a terminal (replace the values):

```powershell
curl.exe -X POST "https://generativelanguage.googleapis.com/v1beta/openai/chat/completions" `
  -H "Authorization: Bearer YOUR_API_KEY" -H "Content-Type: application/json" `
  -d "{\"model\":\"gemini-3.6-flash\",\"messages\":[{\"role\":\"user\",\"content\":\"hi\"}]}"
```

A JSON reply with `choices[0].message.content` means the endpoint and key are
good; anything else tells you the exact provider error.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Replies are always identical canned text | AI not configured, or provider erroring | Check all three variables; run the curl test above; check the dev-server console for the thrown error from `lib/ai.ts` |
| `AI reply generation is not configured` in logs | `AI_BASE_URL` or `AI_MODEL` is empty | Fill both in `.env` |
| Provider returns **401 / 403** | Key is wrong, revoked, or missing | Generate a new key and paste it again |
| Provider returns **429** | Free-tier rate/quota limit hit | Wait for the limit window, or switch provider/model |
| Provider returns **404** | Wrong base URL or model name | Compare against the table above; the URL must NOT include `/chat/completions` |
| Replies get cut mid-sentence | Token budget exhausted (the code uses `max_tokens: 1200` and rejects unfinished replies) | Use a faster/less reasoning-heavy model, or ask the maintainers to raise the cap |

## Security rules

- `.env` is **gitignored** - never commit it, and never paste a real key into
  `env.example`, chat messages, or screenshots.
- `env.example` must only ever contain the placeholder `your-api-key-here`.
- If a real key ever ends up in git history, **revoke it immediately** in the
  provider's dashboard - removing it from files is not enough, history keeps it.
- On deployed hosting (Vercel/Railway/etc.), set the three `AI_*` variables in
  the hosting dashboard's environment variables instead of committing them.
